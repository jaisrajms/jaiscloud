# Terraform differential: record real GCP, replay the emulator

`tools/tfdifferential` is the TF6 real-GCP oracle for the Terraform suite. It
records a curated corpus against a real project, normalizes it, and replays the
same modules against `jaiscloud-gcp`, diffing the two. It exists because every
other Terraform gate in this repository is emulator-only: a provider-side
difference that also exists on real GCP (the empty-label quirk, TGM15) can be
mistaken for an emulator bug, and an emulator bug can hide behind "the module
converges".

This is not the spec. Real GCP (and the provider) wins; the recording is a
regression gate and a divergence finder.

## Layout

| path | contents |
|---|---|
| `corpus.yaml` | the cases, their module directory and whether real GCP may run them |
| `cases/` | root modules written for this differential (self-contained) |
| `golden/` | one normalized JSON per recorded case + `manifest.json` (sha256 per file) |
| `classifications.yaml` | one row per allowed difference (verdict, ledger id, reason) |
| `report.md` | generated by a compare run: cases, differences, not-recorded |
| `../../../tools/tfdifferential/` | the record/compare/check tool |
| `../../../docs/gcp/terraform-compatibility.md` | the trust boundary this corpus backs |

Cases reuse the composition patterns where the shape already exists
(`../patterns/01-cmek`); a new case is a directory with `main.tf` (and
optionally `outputs.tf`) that accepts the shared `endpoint`, `project` and
`region` variables. **Do not add a `provider.tf`**: the tool copies
`patterns/provider.tf`, whose custom endpoints become `null` when `endpoint` is
empty, so the real and emulated runs use the same provider block.

## Record (credentialed, never CI)

```bash
# needs Application Default Credentials and a real project
gcloud auth application-default login
make record-gcp-terraform-differential                     # project defaults to parity-diff-jaiscloud
make record-gcp-terraform-differential PROJECT=my-project  # or name another
```

The target runs every `real_gcp: safe` case, applies it, captures the state and
the re-plan, destroys it, then writes the goldens + manifest. It refuses to run
when `GOOGLE_OAUTH_ACCESS_TOKEN` is set (that is the fake emulator token) and
looks the project number up with `gcloud` because real APIs embed it in resource
names.

The CMEK case needs the project's service agents to hold
`roles/cloudkms.cryptoKeyEncrypterDecrypter` (one-time project setup):

```bash
gcloud beta services identity create --service=secretmanager.googleapis.com
gcloud projects add-iam-policy-binding "$PROJECT" \
  --member="serviceAccount:$(gcloud storage service-agent --project="$PROJECT")" \
  --role=roles/cloudkms.cryptoKeyEncrypterDecrypter
gcloud projects add-iam-policy-binding "$PROJECT" \
  --member="serviceAccount:bq-$(gcloud projects describe "$PROJECT" --format=value(projectNumber))@bigquery-encryption.iam.gserviceaccount.com" \
  --role=roles/cloudkms.cryptoKeyEncrypterDecrypter
```

Every case destroys its stack even when a step fails. KMS key rings cannot be
deleted by the API (the provider does not call a delete either), so names carry
a per-run suffix; a recording leaves the rings behind, which is expected and
free.

## Compare (offline replay)

```bash
make test-gcp-terraform-differential
# or against an already-running emulator:
go run ./tools/tfdifferential -mode compare -endpoint http://localhost:8080
```

The replay verifies `golden/manifest.json` first (a hand-edited golden fails
loudly), runs the same cases against the emulator, normalizes them the same way
and diffs. Every difference must match a `classifications.yaml` rule; anything
unclassified fails the run and is printed with the real and emulator values. The
markdown report is rewritten at `differential/report.md`.

`make check-gcp-terraform-differential` is the offline hygiene gate (no
Terraform, no network): it verifies the manifest, parses every golden and
classification, and requires a golden for every `real_gcp: safe` case. The same
check runs in `make gcp-ci-preflight` through `go test ./tools/tfdifferential/`.

## What a golden contains

```json
{
  "case": "foundation",
  "provenance": {
    "project": "parity-diff-jaiscloud",
    "region": "us-central1",
    "recorded_at": "2026-11-08T03:06:37Z",
    "terraform_version": "1.16.3",
    "provider_version": "hashicorp/google 7.46.2",
    "platform": "linux_amd64",
    "case_dir": "cases/foundation"
  },
  "resources": { "google_storage_bucket.diff": { "...": "post-apply state" } },
  "plan": { "google_storage_bucket.diff": { "actions": ["create"], "unknown": ["id", "..."] } },
  "replan": {}
}
```

`resources` is the post-apply state keyed by resource address. `plan` is the
first plan's diff set — **only** actions and the paths of computed unknowns, so
no value (and no secret) is recorded. `replan` is empty when Terraform reports
No changes after apply.

### Normalization

The normalizer folds values that cannot match across runs, not fields that might
be missing:

| folded | placeholder |
|---|---|
| project id and project number | `<project>` |
| the run suffix (`{suffix}` in corpus variables) | `<suffix>` |
| real/emulator origin in self-links and media links | `<origin>` |
| `etag`, `fingerprint`, `unique_id` | `<etag>`, `<fingerprint>`, `<unique-id>` |
| `generation`, `metageneration` | `<generation>` |
| `create_time`, `update_time`, `time_created`, `updated`, `last_modified_time`, `effective_time`, … | `<timestamp>` |
| numeric ids, generations, `number` | `<numeric-id>` / `<number>` |
| `?generation=<digits>` in a media link | `?generation=<generation>` (presence is kept) |
| the operator's consumer email in a default ACL | `<user>` |
| Terraform `sensitive_values` leaves | dropped |
| `timeouts` | dropped |

A field that one side omits still diffs, which is the point: a missing
`self_link` or query parameter is visible in the report.

## Adding or re-recording a case

1. Add a directory under `cases/` (or point at an existing pattern) and a
   `corpus.yaml` entry. Use `real_gcp: safe` only for a case that is cheap,
   self-cleaning and reversible on a shared real project; otherwise
   `real_gcp: excluded` with the reason (an excluded case has no golden and is
   listed under "Not recorded" in the report).
2. Record it: `make record-gcp-terraform-differential CASES=my-case`.
3. Compare: `make test-gcp-terraform-differential`, then classify every
   difference in `classifications.yaml`. An `emulator-gap` row needs an `id` and
   a `branch`; every other verdict needs a `reason`.
4. Re-run `make check-gcp-terraform-differential`, commit the golden, manifest
   and report.

Re-record after a provider bump (the drift workflow will flag it) or after a fix
that removes a classified difference; then delete the now-unreachable rule.

## Determinism

The run suffix is random but folded, so a replay with a different suffix
produces the same normalized document. Lists are compared in order, maps by
sorted key, and differences are sorted by path. Two recordings of the same
commit on the same provider version differ only in provenance (timestamp) and in
values that normalize to the same placeholder.
